# T0.15: Four languages

**Status:** ✅ Done · **Ticket:** [TICKET.md](TICKET.md) · **Choices and trade-offs:** [IMPLEMENTATION.md](IMPLEMENTATION.md) · **Review:** [REVIEW.md](REVIEW.md)

## 🔭 What it does

- Every person has a language (English, French, German or Spanish, English by default), stored with the person.
- Python messages live in Babel catalogues in four languages, in a new package, and a `Translator` gives a message in a person's language.
- The front ends take their texts from FormatJS messages in the four languages, and the four shells switch language without reloading.
- CI fails when a Python or a front-end message lacks one of the four languages.

## ⚙️ How it works

1. **The language is a shared enum:** `Language` holds `en`, `fr`, `de`, `es` in [`packages/python/swarm-models/src/swarm_models/models/enums.py:8-21`](https://github.com/gpbcom/swarm/blob/a2e43f7e74d65cc12a43507ec33f673fd2bc62e3/packages/python/swarm-models/src/swarm_models/models/enums.py#L8-L21).
2. **The person carries it:** `Person.language` defaults to English ([`person.py:48`](../../../backend/swarm-models/src/swarm_models/people/person.py#L48)); its validator turns `None` into English and refuses any other value with `SEPersonInvalidLanguage` ([`person.py:109-129`](../../../backend/swarm-models/src/swarm_models/people/person.py#L109-L129)).
3. **The generated types follow:** the JSON Schema, the Rust structs and the TypeScript types are regenerated with `Language` ([`swarm_models.schema.json:336`](../../../backend/swarm-models/schemas/swarm_models.schema.json#L336), [`generated.rs:430`](../../../rust/swarm-models/src/generated.rs#L430), [`models.ts`](../../../frontend/packages/live/src/generated/models.ts)).
4. **Python catalogues are read from disk:** `PoCatalogStore` reads `swarm.pot` and `<lang>/LC_MESSAGES/swarm.po` with Babel, after checking each line for syntax Babel would accept silently, and raises `SECatalogUnreadableError` on a failure ([`po_catalog_store.py:76-99`](../../../backend/swarm-storage/src/swarm_storage/shared/i18n/po_catalog_store.py#L76-L99)). The shipped catalogues are [`swarm.pot`](../../../backend/swarm-storage/src/swarm_storage/shared/i18n/locales/swarm.pot) and the four `.po` files, for example [`en`](../../../backend/swarm-storage/src/swarm_storage/shared/i18n/locales/en/LC_MESSAGES/swarm.po).
5. **Python messages are checked:** `CatalogChecker.find_missing()` walks every id of the template and every `Language`, and reports a `MissingTranslation` when the entry is absent, empty or fuzzy ([`catalog_checker.py:38-57`](../../../backend/swarm-service/src/swarm_service/shared/i18n/catalog_checker.py#L38-L57), [`catalog_checker.py:82-105`](../../../backend/swarm-service/src/swarm_service/shared/i18n/catalog_checker.py#L82-L105)). The problems are the `MessageProblem` enum ([`enums.py:8-19`](https://github.com/gpbcom/swarm/blob/a2e43f7e74d65cc12a43507ec33f673fd2bc62e3/packages/python/swarm-i18n/src/swarm_i18n/models/enums.py#L8-L19)).
6. **Python messages are translated:** `Translator.translate()` refuses an id absent from the template, returns the text in the language, and falls back to English with a WARNING when the translation is empty ([`translator.py:80-104`](../../../backend/swarm-service/src/swarm_service/shared/i18n/translator.py#L80-L104)). `translate_for()` uses `person.language` ([`translator.py:106-117`](../../../backend/swarm-service/src/swarm_service/shared/i18n/translator.py#L106-L117)).
7. **The Python check runs as a command:** `swarm-i18n-check` ([`pyproject.toml:13-14`](https://github.com/gpbcom/swarm/blob/a2e43f7e74d65cc12a43507ec33f673fd2bc62e3/packages/python/swarm-i18n/pyproject.toml#L13-L14)) calls `main()`, which exits 0 when complete, 1 and one line per problem when a translation is missing, 2 when a catalogue is unreadable ([`check_catalogs.py:15-39`](https://github.com/gpbcom/swarm/blob/a2e43f7e74d65cc12a43507ec33f673fd2bc62e3/packages/python/swarm-i18n/src/swarm_i18n/api/cli/check_catalogs.py#L15-L39)).
8. **The front-end messages are checked:** `findMissing()` compares the four JSON catalogues with English and reports `missing`, `empty` or `unknown` ids ([`find-missing.ts:11-31`](../../../frontend/packages/i18n/src/find-missing.ts#L11-L31)). The `check-messages` script reads `src/messages/<lang>.json` and exits 1 on any problem ([`check-messages.ts:23-30`](../../../frontend/packages/i18n/scripts/check-messages.ts#L23-L30), [`package.json:12`](../../../frontend/packages/i18n/package.json#L12)).
9. **CI runs both checks:** a step in the `packages` job runs `uv run swarm-i18n-check` ([`python.yml:182-183`](../../../.github/workflows/python.yml#L182-L183)) and a step in the TypeScript job runs `check-messages` where a project has it ([`typescript.yml:45-46`](../../../.github/workflows/typescript.yml#L45-L46)).
10. **The provider applies the language:** `I18nProvider` resolves the person's language, falling back to English ([`i18n-provider.tsx:16-18`](../../../frontend/packages/i18n/src/i18n-provider.tsx#L16-L18), [`languages.ts:18-20`](../../../frontend/packages/i18n/src/languages.ts#L18-L20)), follows a changed prop without remounting ([`i18n-provider.tsx:20-23`](../../../frontend/packages/i18n/src/i18n-provider.tsx#L20-L23)), sets `document.documentElement.lang` ([`i18n-provider.tsx:25-27`](../../../frontend/packages/i18n/src/i18n-provider.tsx#L25-L27)) and gives react-intl the messages of the language ([`i18n-provider.tsx:34-40`](../../../frontend/packages/i18n/src/i18n-provider.tsx#L34-L40)). `useLanguage()` exposes `language` and `setLanguage` ([`i18n-provider.tsx:43-49`](../../../frontend/packages/i18n/src/i18n-provider.tsx#L43-L49)). The messages are in [`en.json`](../../../frontend/packages/i18n/src/messages/en.json), [`fr.json`](../../../frontend/packages/i18n/src/messages/fr.json), [`de.json`](../../../frontend/packages/i18n/src/messages/de.json) and [`es.json`](../../../frontend/packages/i18n/src/messages/es.json), assembled in [`catalogues.ts:9`](../../../frontend/packages/i18n/src/catalogues.ts#L9).
11. **The frames show message ids:** side bar items, Hold and Abort now carry a `messageId` instead of a label ([`parts.ts:21-24`](../../../frontend/packages/ui/src/frames/parts.ts#L21-L24)). `SideBar` and `GroundControlFrame` translate them with `intl.formatMessage` ([`SideBar.tsx:26`](../../../frontend/packages/ui/src/frames/shell/SideBar.tsx#L26), [`GroundControlFrame.tsx:43-46`](../../../frontend/packages/ui/src/frames/apps/GroundControlFrame.tsx#L43-L46)).
12. **The shells use the provider:** each shell wraps its app in `I18nProvider` ([`client-portal/src/main.tsx:17-19`](../../../frontend/apps/client-portal/src/main.tsx#L17-L19), [`ground-control/src/main.tsx:18-20`](../../../frontend/apps/ground-control/src/main.tsx#L18-L20), [`mission-studio/src/main.tsx:18-20`](../../../frontend/apps/mission-studio/src/main.tsx#L18-L20), [`back-office/src/main.tsx:17-19`](../../../frontend/apps/back-office/src/main.tsx#L17-L19)) with `language={undefined}`, and puts `status.language` in its status bar ([`client-portal/src/App.tsx:8-13`](../../../frontend/apps/client-portal/src/App.tsx#L8-L13)).
