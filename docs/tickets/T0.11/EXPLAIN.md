# T0.11: Keycloak and gateway authentication

**Status:** ✅ Done · **Ticket:** [TICKET.md](TICKET.md) · **Choices and trade-offs:** [IMPLEMENTATION.md](IMPLEMENTATION.md) · **Review:** [REVIEW.md](REVIEW.md)

## 🔭 What it does

- Deploys Keycloak as the global identity layer: one realm, one role per persona, a second factor for the five staff roles, five-minute access tokens, rotated refresh tokens and PKCE clients for the apps.
- Gives each person a fixed Operator that only an administrator can set, carried in the access token.
- Makes the gateway verify every call: a missing token, an expired token, a wrong signature or another Operator's identifier is refused and logged.
- Adds a Terraform module and chart wiring so the dev cell can start Keycloak with a generated admin secret.

## ⚙️ How it works

1. **Realm import:** Keycloak starts with `--import-realm` and reads the realm file from a ConfigMap, in [`deploy/charts/keycloak/templates/deployment.yaml:23`](../../../deploy/charts/keycloak/templates/deployment.yaml#L23).
2. **Token and client settings:** the realm sets a 300 s access token and refresh tokens that cannot be reused, in [`deploy/charts/keycloak/files/swarm-realm.json:6-7`](../../../deploy/charts/keycloak/files/swarm-realm.json#L6-L7). Each client requires PKCE with `S256`, for example at [`deploy/charts/keycloak/files/swarm-realm.json:155`](../../../deploy/charts/keycloak/files/swarm-realm.json#L155).
3. **Second factor:** one conditional flow per staff role asks for the one-time code, for example [`deploy/charts/keycloak/files/swarm-realm.json:348`](../../../deploy/charts/keycloak/files/swarm-realm.json#L348).
4. **Operator claim:** the `swarm` scope maps the user attribute `operator_id` to the token claim of the same name, in [`deploy/charts/keycloak/files/swarm-realm.json:112-118`](../../../deploy/charts/keycloak/files/swarm-realm.json#L112-L118). The attribute is declared in the user profile with view and edit for administrators only, in [`deploy/charts/keycloak/files/swarm-realm.json:503-510`](../../../deploy/charts/keycloak/files/swarm-realm.json#L503-L510), so a person cannot change their own Operator (BR-008).
5. **Admin secret:** Terraform generates the administrator password and stores it as a Kubernetes secret, in [`deploy/terraform/modules/self-hosted/identity/main.tf:12-26`](../../../deploy/terraform/modules/self-hosted/identity/main.tf#L12-L26). The dev cell enables the module through `identity_enabled`, in [`deploy/terraform/cells/dev/main.tf:63-67`](../../../deploy/terraform/cells/dev/main.tf#L63-L67).
6. **Install at start-up:** the gateway application installs the access check after building the REST app, in [`services/gateway/src/gateway/api/rest/gateway_rest_app.py:65`](../../../services/gateway/src/gateway/api/rest/gateway_rest_app.py#L65). [`AccessInstaller.install`](../../../services/gateway/src/gateway/api/rest/auth/access_installer.py#L40) stores the `AccessService` on the app state and registers one handler for the access and identity errors.
7. **Per route:** a route declares `Depends(RouteAccess([...roles]))`. [`RouteAccess.__call__`](../../../services/gateway/src/gateway/api/rest/auth/route_access.py#L97) reads the bearer token, reads `operator_id` from the path parameters and asks the service to authorise.
8. **Signing key:** [`KeycloakJwksClient.signing_key`](../../../services/gateway/src/gateway/clients/keycloak/keycloak_jwks_client.py#L83) answers from its cache, or refetches the key set from the realm's certificates endpoint ([`:57`](../../../services/gateway/src/gateway/clients/keycloak/keycloak_jwks_client.py#L57)), and raises when the `kid` is still unknown.
9. **Token check:** [`TokenVerifier.verify`](../../../services/gateway/src/gateway/service/auth/token_verifier.py#L149) refuses a missing token, then [`_claims`](../../../services/gateway/src/gateway/service/auth/token_verifier.py#L90) checks signature, issuer, audience and expiry with RS256 and maps an expired token to its own error. The claims become a [`Caller`](../../../services/gateway/src/gateway/models/auth/caller.py#L20) with person, Operator and roles.
10. **Role and Operator check:** [`AccessGuard.check`](../../../services/gateway/src/gateway/service/auth/access_guard.py#L38) refuses a call that names another Operator than the caller's, then a caller holding none of the roles.
11. **Refusal:** [`AccessErrorHandler.__call__`](../../../services/gateway/src/gateway/api/rest/auth/access_error_handler.py#L58) logs the refusal at `WARNING`, answers a `problem+json` and adds `WWW-Authenticate` for a 401.

## 🧪 How to test it

```bash
uv run pytest services/gateway/tests/service/auth -n 2
uv run pytest services/gateway/tests/api/rest -n 2
uv run pytest tests/deploy/charts/keycloak -n 2
uv run mypy services/gateway/src
(cd deploy/terraform/modules/self-hosted/identity && terraform init -backend=false && terraform test)
```

The first three show the three acceptance cases (no token, expired token, another Operator) and the realm settings.

## 📝 Assumptions accepted

- Declaring `operator_id` in Keycloak's declarative user profile, with view and edit for admin only and no `unmanagedAttributePolicy`, is an acceptable way to give each person a fixed Operator under BR-008. The organisation-per-Operator model can replace it later without changing the claim the gateway reads.
