# T0.17: Observability base

**Status:** ✅ Done · **Ticket:** [TICKET.md](TICKET.md) · **Choices and trade-offs:** [IMPLEMENTATION.md](IMPLEMENTATION.md) · **Review:** [REVIEW.md](REVIEW.md)

## 🔭 What it does

- Every Python app, the synthetic Drones and the browser can export traces, metrics and logs over OTLP/HTTP, off by default.
- One trace follows a SquadFrame from the flight engine tick, over NATS, to the browser worker.
- Secrets, personal data and `drone_id` on metrics are removed before export, and again in the collector.
- The dev cell gains a collector, Prometheus, Loki, Tempo and Grafana.

## ⚙️ How it works

1. **Start-up:** each app's `main()` builds its `SignalsConfig` and calls the configurator, for example in [`backend/apps/flight-engine/src/swarm_flight_engine/main.py:35`](../../../backend/apps/flight-engine/src/swarm_flight_engine/main.py#L35).
2. **Providers:** [`SignalsConfigurator.configure`](../../../backend/libs/swarm-web/src/swarm_web/signals/signals_configurator.py#L145) builds the resource ([line 103](../../../backend/libs/swarm-web/src/swarm_web/signals/signals_configurator.py#L103)), the tracer ([line 115](../../../backend/libs/swarm-web/src/swarm_web/signals/signals_configurator.py#L115)) and the meter ([line 132](../../../backend/libs/swarm-web/src/swarm_web/signals/signals_configurator.py#L132)), and does nothing when signals are off.
3. **Operator and Mission on spans:** [`MissionSpanProcessor.on_start`](../../../backend/libs/swarm-web/src/swarm_web/signals/mission_span_processor.py#L43) copies `operator_id` and `mission_id` from baggage onto each span.
4. **The tick:** [`MissionActor._tick`](../../../backend/swarm-service/src/swarm_service/flight/missions/mission_actor.py#L109) sets fresh baggage, opens the root span ([line 121](../../../backend/swarm-service/src/swarm_service/flight/missions/mission_actor.py#L121)), publishes, then counts the frame and records the duration.
5. **Trace parent in the frame:** [`SquadFrameBuilder._trace_parent`](../../../backend/swarm-service/src/swarm_service/flight/missions/squad_frame_builder.py#L84) formats the current span as a W3C `traceparent`, set on the frame at [line 210](../../../backend/swarm-service/src/swarm_service/flight/missions/squad_frame_builder.py#L210). The field is validated in [`squad_frame.py:110`](../../../backend/swarm-models/src/swarm_models/telemetry/squad_frame.py#L110).
6. **Over NATS, out:** [`NatsTraceContext.inject`](../../../backend/libs/swarm-nats/src/swarm_nats/tracing/nats_trace_context.py#L30) adds the propagated headers; the publisher wraps the send in a producer span ([`squad_frame_publisher.py:74`](../../../backend/swarm-clients/src/swarm_clients/flight/leaf/squad_frame_publisher.py#L74)).
7. **Over NATS, in:** [`NatsTraceContext.extract`](../../../backend/libs/swarm-nats/src/swarm_nats/tracing/nats_trace_context.py#L48) reads them back, and the feed client delivers the frame in a consumer span of that trace ([`mission_feed_client.py:69`](../../../backend/swarm-clients/src/swarm_clients/gateway/nats/mission_feed_client.py#L69)).
8. **Redaction before export:** [`RedactingSpanExporter.export`](../../../backend/libs/swarm-web/src/swarm_web/signals/redacting_span_exporter.py#L112) removes sensitive keys and URL queries; [`MetricLabelGuard.export`](../../../backend/libs/swarm-web/src/swarm_web/signals/metric_label_guard.py#L170) drops `drone_id` from metrics.
9. **Browser decode:** [`decodeSquadFrame`](../../../frontend/packages/live/src/protocol/squad-frame-decoder.ts#L80-L84) keeps `trace_parent` when it is text, leaves it out when null and refuses other types.
10. **Browser span:** the worker calls [`traceSquadFrame`](../../../frontend/packages/live/src/worker/live-worker-core.ts#L111), which continues the trace in [`frame_tracing.ts:9-13`](../../../frontend/packages/live/src/tracing/frame_tracing.ts#L9-L13) through `Signals` of [`@swarm/observability`](../../../frontend/packages/observability/src/signals.ts#L45).
11. **Collector:** [`configmap.yaml`](../../../infra/charts/otel-collector/templates/configmap.yaml#L48) applies redaction, `drone_id` removal and tail sampling (errors, slow, 5 % of the rest) per pipeline ([lines 77-85](../../../infra/charts/otel-collector/templates/configmap.yaml#L77-L85)).

## 📝 Assumptions accepted

- No feature, use case or business rule is linked: the ticket builds on 08-observability#signals alone, which settles what is built.
- No budget is touched: the cost per tick per Mission is one span and two metric records, never one per Drone; in the browser it is one span per frame with no per-Drone attribute.
- No screen is touched: only `frontend/packages` change, and no front-end app does.
- The trace starts at the flight engine tick, because MAVLink carries no trace context.
- Acceptance criterion 1 is proven by tests along the whole path, because the gateway and the flight engine are not deployed in the dev cell yet. The browser decode step is now fixed and tested.
- Wiring the collector endpoint into Ground control and exposing the collector to browsers (CORS) are left to a front-end ticket, because that work is outside this ticket's area.
